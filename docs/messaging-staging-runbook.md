# Runbook — تجربة مركز الرسائل على Staging (قبل أي تفعيل)

هذا الدليل لبيئة **Staging فقط**، ويُنفَّذ **بقرار مستقل من المالك** بعد اعتماد الواجهة. لا يُنفَّذ أي جزء منه على
Production. الأوامر تُنسخ حرفيًا في **Terminal تطبيق Staging في Coolify** (داخل الحاوية، المجلد `/app`). لا تكتب
`DATABASE_URL` ولا `JWT_SECRET` ولا مفاتيح S3 في أي أمر — تُقرأ من Environment Variables. السكربتات لا تطبع روابط
ولا كلمات سر ولا مفاتيح تخزين.

> الوضع الحالي: `MESSAGING_ENABLED` غير مضبوط = **معطّل**. لا Push ولا Deploy ولا Migration حتى يُقرَّر ذلك صراحةً.

## 0) المتطلبات قبل البدء

- التخزين الدائم مضبوط في Staging: `S3_BUCKET` و`S3_ACCESS_KEY_ID` و`S3_SECRET_ACCESS_KEY` (+ `S3_ENDPOINT`
  لـR2/MinIO). **بدونه يرفض الرفع بـ503 ولا يوجد تخزين محلي في Staging** — هذا مقصود.
- `DEPLOY_ENV=staging` مضبوط صراحةً.
- Backup حديث لقاعدة Staging.
- جهازان حقيقيان: **iPhone (Safari)** و**Android (Chrome)**، على HTTPS (الميكروفون لا يعمل بدون سياق آمن).
- حسابا تجربة في شركة Staging: موظف عادي، ومدير، والمالك (`super_admin`). وموظف في **شركة أخرى** للعزل.

```bash
node -v && ls dist/scripts | grep -E "0043|purge" && node -e "require('mysql2/promise');require('@aws-sdk/client-s3');console.log('deps ok')"
```

## 1) الترحيلة 0043 — check ثم apply ثم check

```bash
node dist/scripts/migrate-0043-messaging.mjs --check
```

المتوقع: `غير مطبَّقة` والفهرسان المركّبان `present` (من 0040/0041). أي `partial` = **توقف** وراجع (لا إكمال تلقائي).

```bash
node dist/scripts/migrate-0043-messaging.mjs --apply --confirm "APPLY 0043 TO <اسم قاعدة Staging كما طبعه --check>"
node dist/scripts/migrate-0043-messaging.mjs --check
```

المتوقع: `مطبَّقة ومطابقة للمواصفة بالكامل` و9 جداول `msg_*`.

## 2) تشغيل العلم على Staging فقط

في Coolify (تطبيق Staging): `MESSAGING_ENABLED=true` ثم Redeploy. لا تلمس Production.

## 3) سيناريوهات الواجهة (كل خطوة: ✓ أو ✗ مع لقطة)

| # | السيناريو | المتوقع |
|---|-----------|---------|
| 1 | المالك يفتح `/messages` | الإعلانات + فريق الشركة + قناة لكل نشاط تُنشأ تلقائيًا، ورسالة سياسة الخصوصية مرة واحدة |
| 2 | موظف من البوابة يفتح `/my-messages` | نفس القنوات حسب نشاطه، وزر «الرسائل» يظهر في رأس لوحته |
| 3 | موظف يرسل في الفريق، والآخر مفتوح على نفس المحادثة | تصل خلال ~4 ثوانٍ، والعدّاد في القائمة خلال ~20 ثانية |
| 4 | ضغط مزدوج سريع على «إرسال» وعلى «إنشاء المجموعة» | رسالة واحدة / مجموعة واحدة |
| 5 | تعديل رسالة ثم حذفها | «عُدّلت» تفتح السجل؛ المحذوفة «تم حذف هذه الرسالة» بلا نص |
| 6 | موظف بلا `messages.announce` في الإعلانات | قراءة فقط + زر «اطّلعت»؛ المالك يرى «اطّلع N» |
| 7 | المالك **بلا منح** `messages.view_private` | لا قسم «اطلاع المالك» |
| 8 | منح `messages.view_private` للمالك من «صلاحيات الأدوار» (ويُرفض لأي دور آخر) | قسم «اطلاع المالك — قراءة فقط ومسجَّل»، الفتح قراءة فقط بلا كتابة/تفاعل/علامة قراءة |
| 9 | موظف شركة أخرى يفتح رابط محادثة من الشركة الأولى | «المحادثة غير موجودة» |
| 10 | سحب `messages.use` لدور | الطلب التالي مرفوض، والزر يختفي بعد تحديث الصفحة |
| 11 | قطع الإنترنت ثم إعادته | شريط «لا يوجد اتصال»، توقف التحديث، استئناف فوري عند العودة |
| 12 | ترك التبويب في الخلفية دقيقة | لا طلبات أثناءها (أدوات المطوّر → Network)، وتحديث فوري عند العودة |
| 13 | قراءة رسائل قديمة أثناء وصول جديدة | لا يُسحب المستخدم للأسفل؛ زر «رسائل جديدة» يظهر |
| 14 | «تحميل رسائل أقدم» | تضاف أعلى القائمة بلا تكرار ولا قفز في الموضع |
| 15 | تكبير الخط 125% من «تخصيص العرض» أثناء الوقوف أسفل المحادثة | يبقى على آخر رسالة |

## 4) الصوت على أجهزة حقيقية (إلزامي قبل أي تفعيل خارج Staging)

لكل من **iPhone Safari** و**Android Chrome**:

1. أول ضغطة على الميكروفون → نافذة إذن المتصفح → «سماح». العداد يتحرك `0:03 / 5:00`.
2. «إيقاف» → معاينة تُشغَّل محليًا → «إرسال». الطرف الآخر يرى المدة **التي قاسها السيرفر** (تقريبًا مثل المسجّلة).
3. الطرف الآخر يضغط تشغيل → يعمل (Safari يحتاج Range — مدعوم)، السرعات 1×/1.5×/2×، ويظهر للمرسل «سمعها 1».
4. رفض الإذن من إعدادات المتصفح → رسالة «تم رفض الوصول للميكروفون…» بوضوح.
5. تسجيل حتى 5:00 → يتوقف تلقائيًا؛ محاولة ملف مزوّر/كبير عبر الأدوات → 415/413 برسالة عربية.
6. الخروج من المحادثة أثناء التشغيل → يتوقف الصوت. تسجيل الخروج أثناء تسجيل → يُطفأ الميكروفون (مؤشر المتصفح يختفي).
7. التحقق من التخزين (قراءة فقط): الملف تحت `msg/<tenantId>/voice/…` في الـBucket، ولا رابط عام له (فتح المفتاح مباشرة من الـBucket العام يرفض).

سجّل نوع الملف الناتج لكل جهاز (WebM/Opus على Android، MP4/AAC على iPhone) والمدة المقاسة مقابل الفعلية.

## 5) مهمة حذف المرفقات المنتهية (6 أشهر)

```bash
node dist/scripts/purge-message-attachments.mjs
```

(dry-run افتراضيًا: عدد المستحق فقط). الحذف الفعلي فقط بقرار، ويمكن جدولته يوميًا لاحقًا:

```bash
node dist/scripts/purge-message-attachments.mjs --apply --limit 500
```

## 6) الرجوع

- إطفاء العلم: احذف `MESSAGING_ENABLED` (أو `false`) ثم Redeploy — الواجهة تعرض «غير متاح» ولا طلبات إضافية.
- Rollback للترحيلة **قبل وجود أي رسالة فقط**:
  `node dist/scripts/migrate-0043-messaging.mjs --rollback --confirm "ROLLBACK 0043 TO <db>"` (يرفض مع بيانات).

## نقاط التوقف

- أي `partial` في 0043، أو 503 في الرفع (التخزين غير مضبوط)، أو فشل تشغيل على iPhone/Android = **توقف وتقرير**.
- لا تفعيل على Production قبل اعتماد نتيجة القسم 4 على الجهازين.

## ما لا يفعله هذا الـRunbook

- لا يفعّل أي شيء على Production، ولا ينفّذ SQL يدويًا، ولا يمنح `messages.view_private` تلقائيًا.
